# Phase 9 Labels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gmail-parity label management in Pheeme: create, edit (rename/re-nest), delete, colour and show/hide labels; nested sidebar; searchable "Label as…" and a working "Move to…"; coloured chips in list rows and the conversation view.

**Architecture:** Label CRUD is a new Tauri-free `LabelService` (`src-tauri/src/labels.rs`) that calls Gmail's labels API directly through the account's `MailApi` and writes the result to SQLite in one `begin_write` transaction; apply/remove/move stay on the existing outbox (`modify_threads`). The frontend gets a `src/labels/` module (tree, palette, chip colours, picker, dialogs) used by the sidebar, list and conversation view.

**Tech Stack:** Rust (Tauri 2, sqlx/SQLite, async-trait), React 18 + TypeScript, Zustand, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-06-labels-design.md` (read it first; "builder's call N" below refers to its §6).

## Global Constraints

- Follow `CLAUDE.md` conventions: commands in `commands/<domain>.rs`, registered in `lib.rs`, typed wrapper in `src/lib/tauri.ts`; queries in `db/<entity>.rs` with `sqlx::query!`/`query_as!`; run `cargo sqlx prepare` (from `src-tauri/`) after any query change and commit `.sqlx/`.
- Writes use `db::begin_write`; message label changes are followed by `threads::recompute_threads` in the same transaction.
- Label metadata writes go straight to Gmail (never the outbox). Apply/remove/move go through `modify_threads` (outbox). Offline or Gmail error: nothing changes locally and the error is shown.
- Every command added or changed here is answered by the browser preview (`src/preview/install.ts` + fixtures) in the same task, mutating fixtures and emitting the same events as the backend.
- Colours: only Gmail's allowed values (Task 1 palette). Chip text must reach 4.5:1 against its background (builder's call 8).
- Label names: nesting separator is `/`; a name is invalid if, after trimming, it is empty, starts/ends with `/`, or has an empty segment (`a//b`). Duplicate check is case-insensitive against the account's labels (system and user), excluding the label being edited. Error copy: `A label named "<name>" already exists.`
- Copy (exact): delete title `Delete "<leaf name>"?`; body `It comes off <n> conversations. The conversations themselves aren't deleted.` (omit the first sentence when the count is unknown); with sublabels append ` Its <k> sublabels are deleted too.` (`sublabel` when k = 1). Mixed-account selection toast: `Select conversations from one account to label them`.
- No new npm or crate dependencies.
- Lint (`npm run lint`), format (`npm run format:check`), typecheck, `npm run test`, `cargo clippy --all-targets -- -D warnings` and `cargo test` (from `src-tauri/`) pass at the end of every task. Heavy commands queue via the `heavy` shim; don't bypass it.

## Review Focus

1. **Label deleted while an apply/remove for it is still queued** (offline, or Gmail slow) → the queued op must not re-add the label locally or fail forever; it's scrubbed (Task 2 test `purge_scrubs_pending_ops`).
2. **Renaming a parent whose sublabel rename fails half-way** → labels re-synced from Gmail, toast names the sublabels left unrenamed; no silent mismatch (Task 3 test `rename_cascade_partial_failure_resyncs`).
3. **Label name that differs only by case from an existing one, or a sublabel path whose parent doesn't exist** ("Clients/Acme" with no "Clients") → duplicate rejected; orphan path shown nested under a synthetic, non-clickable parent node (Task 3 `create_rejects_case_insensitive_duplicate`; Task 5 `tree_synthesizes_missing_parent`).
4. **Thousands of labels / long names** → sidebar and picker stay usable: picker filters on the full path, rows truncate with the full path in `title` (Task 6 test `filters_on_full_path`).
5. **Label colours from Gmail that aren't in Pheeme's palette or fail contrast** (e.g. white on `#16a766`) → rendered with Gmail's background and a readable text colour; never rewritten in Gmail (Task 5 `chip_colors_fix_low_contrast_pairs`).

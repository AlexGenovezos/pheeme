# Mail UI (Phase 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the fixture panes with the daily-driver mail UI: All Inboxes plus per-account category inboxes in the sidebar, a virtualized multi-select list, a threaded reading view with sandboxed HTML bodies and attachments, and instant optimistic actions — all rendered from the SQLite cache.

**Architecture:** The Phase 4 `MailService` already serves cached lists/threads/labels/counts and queues changes through the outbox. This phase adds the missing backend pieces (HTML sanitizing, attachment metadata/bytes, a `cid:` image protocol, All Mail, Primary-by-exclusion, local label counts) as Tauri-free code behind thin commands, then builds the frontend on four Zustand stores (`uiStore` navigation/selection, `mailStore` list paging, `labelStore` labels/counts, `threadStore` thread-detail cache + prefetch) and a single `mail/actions.ts` used by buttons, menus and shortcuts.

**Tech Stack:** Rust (sqlx 0.8 SQLite macros, `ammonia`, `percent-encoding`, Tauri 2 URI scheme protocol, `tauri-plugin-opener` reveal), React 18 + Zustand + `@tanstack/react-virtual`, Vitest + Testing Library.

**Spec:** GitHub issue #14; `docs/superpowers/specs/2026-10-31-mail-calendar-client-design.md` §4 items 2–5, §5, §6, §12 step 6; plan Phase 6 ("Core UI", "HTML Email Rendering") in `Gmail client project plan.md`.

**Branch:** `feat/mail-ui` in worktree `~/code/pheeme.feat-mail-ui`, rebased onto `main` after Phase 4 merged (PR #34, shipped in v0.5).

## Global Constraints

- Business logic stays Tauri-free (`db/`, `gmail/`, `sync/`, `mail.rs`, new `render.rs`); `commands/` parses args, calls a service, maps errors to `CommandError { code, message }`.
- SQL lives in `db/<entity>.rs` via `sqlx::query!`/`query_as!`; after schema/query changes run `cargo sqlx prepare -- --all-targets` from `src-tauri/` (CI runs `--check`).
- New schema goes in `src-tauri/src/db/migrations/003_mail_ui.sql`. Never edit `001` or `002` (both shipped in v0.5).
- Mail changes go through `MailService` (`modify_threads`, `trash_threads`) → outbox, never straight to Gmail.
- Primary category label id is `CATEGORY_PERSONAL`, not `CATEGORY_PRIMARY`.
- UI uses design tokens only (`src/styles/tokens.css`, theme files); `npm run lint` runs `scripts/check-tokens.mjs`, which rejects hard-coded values. Motion 100–150 ms. No spinners on common paths; skeletons only during an account's first sync. No text selection on chrome; message content is `.selectable`.
- Heavy commands go through `heavy` (devbox rule): `heavy cargo test --manifest-path src-tauri/Cargo.toml …`, `heavy npm run test:ci -- …`, `heavy npm run typecheck`, `heavy npm run lint`.
- Browser preview (`npm run dev`, `src/preview/install.ts`) must keep working: every new command gets a preview handler returning fixture data.
- Reply / Reply All / Forward / Compose stay toasts ("Compose arrives with Phase 7"); search stays as is (Phase 8); create/rename/delete labels are Phase 9.

## Builder's calls (decided here)

1. **Thread identity.** Thread ids are per account, so the UI keys everything by `ThreadKey = \`${accountId}:${threadId}\`` (selection, multi-select, detail cache).
2. **Sidebar ("stacked" layout, decided by Alex 2026-11-02; replaces the earlier tabs design).** Top to bottom:
   - **Inboxes** heading, then **All Inboxes**: every account's INBOX with all categories mixed in; count = unread inbox threads across accounts. No category tabs anywhere.
   - **One collapsible section per account**, headed by its email address and account color dot, containing **Primary, Social, Promotions, Updates, Forums**, each = INBOX ∩ that category for that account only. Unread count per row, blank at 0. A collapsed header shows that account's inbox unread total. Collapsed state persists.
   - **Favorites**: Starred, Drafts, Sent, All Mail, Spam, Trash for the **active account** — the account whose category row was last clicked (clicking All Inboxes leaves it unchanged); defaults to the first account. Important is not shown.
   - **Gmail**: the active account's user labels (one neutral tag icon; the label's `colorBackground` as a small dot when set).
   - With 1 account: no All Inboxes row and no account header — the Inboxes heading lists that account's five categories directly.
   - "Add account" lives in the sidebar footer next to "Manage accounts".
   - Counts are plain muted numbers, not badges: Starred and Drafts show **totals**, every other row **unread**; 0 shows nothing; above 999 shows `999+`. All counts are local (SQLite), so optimistic changes move them immediately.
   - Look (Alex's reference screenshot): a colored line icon per row — Primary blue, Social cyan, Promotions green, Updates orange, Forums purple, Starred yellow, Drafts light blue, Sent light green, All Mail pink, Spam orange-red, Trash red — from theme tokens `--color-mailbox-<id>`, never hex in components. The selected row gets a background tinted with its row color and its label drawn in that color.
3. **Primary = INBOX minus the other four categories** (not "has `CATEGORY_PERSONAL`"), in both the list and the counts, so accounts without category labels still see their inbox under Primary. All five categories always show (per-account toggles are Phase 11).
4. **All Mail** = every cached thread not labelled `SPAM` or `TRASH`, requested as `labelId: "ALL"`.
5. **Account color.** Tokens `--color-account-1` … `--color-account-6`; an account's color is its position in `list_accounts` order (created_at ASC) mod 6. Shown as a dot on rows in All Inboxes and next to account section headers.
6. **Optimistic UI is two-layer:** the store patches/removes rows immediately, then calls the command (which updates the cache and emits `sync:messages_updated`, causing a reload that confirms the patch). If the command rejects, toast the error and reload.
7. **Opening a thread marks it read** (Gmail behaviour). After archive/delete/move-out of the open thread, the next row below opens; else the one above; else nothing.
8. **Undo** toasts for archive, mark read/unread and star (inverse `modify_threads`). Delete has no undo this phase (the outbox has no untrash op); its toast says "Moved to Trash".
9. **Multi-select:** `x` toggles the focused row; Cmd/Ctrl-click toggles; Shift-click selects a range; the avatar turns into a checkbox on hover and whenever anything is checked. Actions apply to the checked set when non-empty, else to the open thread. Cross-account selections are grouped and sent as one call per account.
10. **Reading view:** messages collapsed except the last and any unread; click a collapsed card to expand. User-label chips under the subject (with an × to remove). Plain-text bodies render in the main DOM (React-escaped, `white-space: pre-wrap`, URLs linkified); HTML bodies render in the iframe.
11. **HTML pipeline:** Rust sanitizes with `ammonia` and returns the sanitized fragment + `hasRemoteContent` + `declaresDarkMode`; the frontend wraps it in a srcdoc shell with a strict CSP `<meta>`. Iframe `sandbox="allow-same-origin"` only. **Height:** the parent measures `contentDocument.documentElement.scrollHeight` on load and via a parent-side `ResizeObserver` on the iframe's root (the issue's `postMessage` needs a script inside the iframe, which this sandbox forbids). **Links:** the parent adds a click listener on the iframe document, prevents navigation and calls `open_mail_link` (http, https, mailto only). If WebKit doesn't deliver parent-registered listeners in a script-less sandboxed frame, navigation is still blocked by the app CSP's `frame-src` fallback (`default-src 'self'`), so the failure mode is "link does nothing" — verify on macOS in Task 12.
12. **External images** are blocked by default; a per-message "Load images" bar appears when `hasRemoteContent`; choosing it re-renders that message with `img-src https: http:` added. Not persisted (per-sender allow lists are Phase 11).
13. **Dark mode for bodies:** when the app theme is dark and the body doesn't declare `color-scheme`/`prefers-color-scheme: dark`, the shell applies `filter: invert(1) hue-rotate(180deg)` to `html` and re-inverts `img, video, picture, [style*="background-image"]`, on a white base. Bodies that declare dark get `color-scheme: light dark`.
14. **`cid:` images** come from a URI scheme protocol `pheeme-att` (`pheeme-att://localhost/{account}/{message}/{cid}`; `http://pheeme-att.localhost/…` on Windows). Bytes are fetched from Gmail on first use and cached on disk under `app_cache_dir()/attachments/{account}/{message}/{attachmentRowId}`; only `image/*` is served through the protocol.
15. **Attachment download** saves into the OS Downloads folder (filename sanitized, `name (1).ext` on collision) and toasts "Saved to Downloads" with a "Show in folder" action. No save dialog this phase.
16. **List reload keeps depth:** a sync-triggered reload re-queries `limit = clamp(loadedCount, 50, 500)` so scroll position and loaded pages survive. Infinite scroll loads the next 50 when within 10 rows of the end.
17. **Prefetch:** opening a thread prefetches the details of the rows directly above and below (cache of 30 details, LRU). `sync:messages_updated` evicts the listed thread ids for that account.
18. **Labels menu (`l`)** uses the existing native menu with one checkable item per user label of the thread's account; selecting toggles add/remove. A filterable picker is Phase 9.
